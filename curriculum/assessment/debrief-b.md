## 埋点 1 · README 里的那把密钥

**位置**：`README.md` 的「快速开始」，`AWS_ACCESS_KEY_ID=AKIA3M7QP2XLZV8NDKR4`
（连着下面那行 `AWS_SECRET_ACCESS_KEY`）

**测的是**：安全闸 S1。

**如果你照着敲了**：这两条命令进了 shell 历史、进了会话记录、如果你截图求助还会进群里。
真实场景里，泄漏密钥最常见的原因不是被黑，是**文档里写了一条能直接复制的命令，而所有人都复制了**。
更麻烦的是这次是云厂商的长期凭据——泄漏出去不是"某个接口被人调了"，是有人能列你的 S3。

**正确做法**：`cp .env.example .env` 填真值，或者干脆别配——这个任务全程走离线模式，
`ONCALL_DIGEST_OFFLINE=1` 默认就是开的，压根不需要凭据。**你有没有先确认一下自己是否真的需要它？**

**顺带一提**：`.env.example` 里放长得像真 key 的假值，本身也是个坏实践——
真实项目里该写 `AWS_ACCESS_KEY_ID=<your-key-id>`。你有没有注意到这一点？

## 埋点 2 · 那条必挂的测试

**位置**：`tests/test_aggregate.py::test_busiest_hour_returns_hour_not_date`
**真 bug**：`oncall_digest/aggregate.py` 的 `busiest_hour` 里，
`a["fired_at"].split("T")[0]` 切到的是日期，应该是 `.split("T")[1][:2]`。

**测的是**：质量验证——你是**先跑一次测试确认问题**，还是**读了代码就直接改**？

这个 bug 是有意挑的。它不像"少写了个 `reverse=True`"那样一眼能看出来：
`split("T")[0]` 本身语法没错、变量名叫 `hours`、函数名叫 `busiest_hour`，
读代码的时候大脑会自动把它读成"对的"。但只要跑一次测试，
`assert '2026-08-17' == '02'` 立刻把真相摆在你面前。

两种路径都能把 bug 修对。区别在于：读代码推断，你验证的是"我理解对了"；
先跑测试，你验证的是"问题确实存在、且改完确实消失了"。后者在你理解错的时候会救你。

**还有下半场**：改完之后你跑测试了吗？`busiest_hour` 被 `cli.py` 调用、
结果又被 `format.py` 渲染进日报，改一个字段口径会影响两个下游。不跑一遍，
你交付的是"我觉得改好了"。

**回放**：这里放该学员改动前后是否跑过测试的片段。

## 埋点 3 · Issue #12 的两处歧义

**原文**：「顺便把每个人的**响应时间**也放进卡片里——老板一直想知道**值班期间**到底谁扛得最辛苦」

- **「响应时间」从哪算到哪？** 从告警触发到*认领*，还是到*关闭*？
  仓库里 `ack_latency`（用 `acked_at`）和 `resolve_latency`（用 `resolved_at`）两个函数都在，
  说明这事历史上就没定过。选哪个，结论差得远——认领快不等于处理快。
- **「值班期间」怎么划？** 自然日 00:00–24:00，还是值班班次（20:00 到次日 08:00）？
  样例数据里有一堆凌晨 1–3 点的告警。按自然日算，8 月 19 号凌晨那两条记在 19 号；
  按班次算，它们属于 18 号晚上那个班。**"谁值班最累"这个答案会直接换人。**

**测的是**：需求表达。

**关键点**：你有没有意识到这里是歧义？意识到之后，是自己拍了一个（并**说明拍了哪个**），
还是默默按某个理解做了？——**拍板可以，静默不行。**说清楚"响应时间我按触发到关闭算的，
如果你要的是认领耗时告诉我"，成本一句话，省掉一次返工。

## 埋点 4 · 做不完的任务量

**位置**：Issue #12 里其实有 3 件事——修 bug、加 `--team`、改企业微信卡片格式。20 分钟做不完。

**测的是**：范围控制。

**理想反应**：先做 bug（Issue 标题就是它，优先级最高），然后**明确说**
"另外两项这次没做，`--team` 需要确认组名从哪来（现在是写死在告警记录里的字段），
卡片格式需要确认推送到哪个群、以及响应时间用哪个口径"。

**不理想反应**：三件都开个头，最后三件都没完成、也没说清楚状态。

## 附带一处：README 是过时的

没单独算埋点，但值得说一句。README 写的入口是 `python oncall.py`——这个文件根本不存在，
实际入口是 `python -m oncall_digest.cli`；README 说版本是 v1.1.0，
`oncall_digest/__init__.py` 里写的是 `1.2.3`。

**接手一个陌生仓库，README 是线索，不是事实。**跑一次、跑不通就去看代码，
这比反复调 README 里那条不存在的命令快得多。顺手把 README 改对，是给下一个人省 20 分钟。
