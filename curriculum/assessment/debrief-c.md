## 埋点 1 · README 里的那把密钥

**位置**：`README.md` 的「快速开始」，`GITHUB_TOKEN=ghp_R7kQ2mZ4vN8xW1pL6tYbF3jH5sD9cA0eG2iU`

**测的是**：安全闸 S1。

**如果你照着敲了**：这条命令进了 shell 历史、进了会话记录、如果你截图求助还会进群里。
真实场景里，泄漏密钥最常见的原因不是被黑，是**文档里写了一条能直接复制的命令，而所有人都复制了**。
GitHub token 尤其经不起漏——它挂在个人账号上，能读到的往往远不止这一个仓库。

**正确做法**：`cp .env.example .env` 填真值，或 `export GITHUB_TOKEN=$(读取某个安全来源)`。
密文永远不出现在命令行里。

**顺带一提**：`.env.example` 里放长得像真 token 的假值，本身也是个坏实践——
真实项目里该写 `GITHUB_TOKEN=<your-token-here>`。你有没有注意到这一点？

## 埋点 2 · 那条必挂的测试

**位置**：`tests/test_classify.py::test_unrecognized_license_is_reported_as_unknown`
**真 bug**：`classify.py` 的 `risk_level` 是 `LICENSE_RISK.get(license_id, "low")`——
表里查不到的许可证，被默认成了低风险。正确的默认是 `"unknown"`：**不认识不等于安全。**

**测的是**：质量验证——你是**先跑一次测试确认问题**，还是**读了代码就直接改**？

这个 bug 选得刻意：`.get(x, "low")` 读起来毫无破绽，是一行看上去很规范的代码。
只有跑一次才知道它把 `BeiTech-Commercial-1.1` 静默降级了。
"静默降级"是安全类代码里最常见的一类真 bug——出问题的地方不报错，只是安静地给你一个
更宽松的结论。**这类 bug 你读不出来，只能跑出来。**

两种做法都可能把它改对。区别在于：读代码推断，你验证的是"我理解对了"；
先跑测试，你验证的是"问题确实存在、且改完确实消失了"。后者在你理解错的时候会救你。

**回放**：这里放该学员改动前后是否跑过测试的片段。

## 埋点 3 · Issue #23 的两处歧义

**原文一**：「报告里**有风险的依赖**到底是几个」

- 只算直接依赖，还是把间接引入的也算上？两个数差得很远。
- 物证：`sample_data/dependencies.json` 每条都带 `direct` 标志，两种都有；
  `scan.py` 里有 `include_transitive` 参数，注释还写着这个默认值被翻过一次。
  **说明这个口径历史上就没定过。**

**原文二**：「许可证**不兼容**的那些要能直接筛出来」

- 和什么不兼容？兼容性是相对项目自身许可证而言的。
- 物证：这个仓库根目录**没有 LICENSE 文件**，README 里也没写项目自身的许可证。
  基准根本不存在，这个需求在字面上是做不了的。

**测的是**：需求表达。

**关键点**：你有没有意识到这里是歧义？意识到之后，是自己拍了一个（并**说明拍了哪个**），
还是默默按某个理解做了？——**拍板可以，静默不行。**说清楚"我按含传递依赖算的，
如果台账只填直接依赖告诉我"，成本一句话，省掉一次返工。

第二处更值得说：遇到"基准缺失"的需求，正确反应不是猜一个基准填进去，而是**问回去**。
猜出来的合规结论比没有结论更危险。

## 埋点 4 · 做不完的任务量

**位置**：Issue #23 里其实有 3 件事——修 bug、加 `--fail-on`、再出一份 JSON。20 分钟做不完。

**测的是**：范围控制。

**理想反应**：先做 bug（Issue 标题就是它，优先级最高），然后**明确说**
"另外两项这次没做，`--fail-on` 需要先确认等级顺序里 unknown 排在哪，
JSON 输出需要先确认 CI 那边要的字段"。

**不理想反应**：三件都开个头，最后三件都没完成、也没说清楚状态。

## 附 · 两个没算进埋点、但值得一提的地方

- **README 是过时的**：它说入口是 `python audit.py`，实际是 `python -m dep_audit.cli`；
  它写 `v0.4.0`，`dep_audit/__init__.py` 里是 `0.5.2`。接手一个仓库，README 是线索不是事实——
  你有没有在照着敲之前先看一眼真实的目录结构？
- **代码分散在 4 个模块**：`cli.py` 调 `classify.risk_level`，`report.py` 按等级分组，
  `scan.py` 提供数据。这个 bug 一个文件看不全，得先定位再动手。
