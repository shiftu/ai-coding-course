> 本文档是多轮产品讨论的收敛结果,所有关键决策均已确认。

## 0. 一页纸摘要

把固定节奏的"两周训练营"升级为一个**随到随学的自适应能力平台**:任何人(新人、实习生、在职员工)进来先做 33 分钟摸底测评,平台据此生成个性化课程路径;学习和作业产生的真实工件(PR、会话、cron 任务)持续更新其四维能力等级;等级兑换真实工作权限(budget、approval 模式);课程内容以"切片 + 元数据"形式存储,由全自动流水线跟随工具发版持续更新。

核心决策一览:

| 决策点 | 结论 |
|---|---|
| 服务边界 | 公司内部为主(新人/实习生/在职员工),架构预留对外可能 |
| 能力模型 | 四维等级(工具操作/需求表达/质量验证/自动化编排)+ 安全合规作为 pass/fail 资格闸 |
| 总等级算法 | 短板决定制:驾照等级 = 四维最低级 |
| 高等级获取 | 测评最高定到 L2;L3/L4 作品制 + 导师背书直升通道 |
| 摸底测评 | 33 分钟三段漏斗:自述 3min + 快筛 10 题 + 沙盒实操 20min(行为信号采集,非答题) |
| 环境形态 | 纯终端(TTY):Linux 容器 + web 终端为主,学员自己的 Mac 为真实环境层;无桌面、无 Mac 池 |
| 内容架构 | 内容即代码:原子切片 + 元数据 + 动态装配,非预制课程 |
| 内容更新 | 尽量全自动:哨兵监测 → 影响圈定 → AI 再生成 → 三道质量闸 → 自动发布 |
| 隐私边界 | 训练营/课程期间采集工件信号;**毕业即停止一切追踪与采集**;个人分数仅本人可见 |
| 规模假设 | 约 100 人/年,峰值并发 30;随到随学为主,集中开营做轻量兼容 |

## 1. 产品定位与设计原则

### 1.1 定位

一个公司内部的 **AI 能力加油站**:自愿来、随时走。它做三件事——

1. **摸底**:用行为观察(而非答题)评估一个人的 AI 协作能力,输出四维等级向量;
2. **补齐**:根据能力短板动态装配个性化微课路径,让有基础的人跳过入门、零基础的人不受挫;
3. **保鲜**:内容跟随工具发版自动更新,人的等级通过自愿续证跟随工具版本保持有效。

平台统一完成工具的部署与配置(一键预配置脚本 + 即开即用沙盒),规避"因安装配置复杂导致直接放弃"。

### 1.2 设计原则

- **行为证据优先**:一切等级判定基于可观察行为与真实工件,不基于自评和答题。"了解 XX"不出现在任何等级描述里,只写"能做到 XX 且有证据"。
- **等级兑换真实权限**:等级不是游戏化装饰,是"驾照"。L2 解锁更高 llm-gateway 月度 budget,L3 解锁 smart approval 模式,L4 允许为团队建生产 cron。权限有效期与工具大版本挂钩(见 §7 续证)。
- **不监控员工**:毕业即停止全部数据采集。平台靠拉力(新版本微课、续证保权限、Demo Day)吸引人回来,不靠推力。保护员工行动和决策的松弛感是硬约束。
- **内容即代码**:课程存 Gitea 仓库,和代码一样走 PR、CI(三道质量闸)、发布流程。吃自己的狗粮——整条内容流水线用 Hermes cron + skill 实现。
- **纯终端**:v1 不做任何桌面环境/屏幕串流。终端向带来即开即用、信号采集干净、会话可低成本录制回放三大红利。

### 1.3 用户画像

| 画像 | 入口场景 | 平台为他做什么 |
|---|---|---|
| 零基础新人/实习生 | 入职第一天,快筛拦截,从 D0 起步 | 完整路径 + 预配置环境,不在沙盒里受挫 |
| 有 AI 经验的新人 | 测评定到 L2,跳过全部入门切片 | 直接进公司工作流特有内容(网关、飞书、红线) |
| 资深 AI 工程师入职 | 导师背书直升 L3/L4 | 免刷作业,直接获得对应权限 |
| 在职员工 | 自愿测评/工具新版续证/查漏补缺 | 10 分钟增量微课,保持等级和权限有效 |
| 管理员/讲师 | 内容审核、新工具评估卡、匿名聚合看板 | 流水线代劳 90% 的内容维护 |

## 2. 能力模型(一切的坐标系)

能力模型是测评、课程切片标签、个人面板三方共用的坐标系,先于一切确定。

### 2.1 四个等级维度(从现有 10 课蒸馏)

每维 L0–L4,锚点全部是**可观察行为 + 平台能采到的证据**:

| 维度 | L1 起步 | L2 上手 | L3 熟练 | L4 沉淀 | 主要证据源 |
|---|---|---|---|---|---|
| **工具操作** | 环境跑通,会用一个入口完成任务 | 会选入口、会 /clear 管理上下文、会恢复会话 | 多工具组合使用、会 skill/profile 定制 | 能给别人搭建环境、独立排障 | gateway 日志、hermes sessions |
| **需求表达** | 能一句话说清任务 | 会先要计划、会收窄范围 | 五要素 spec + 可测量验收标准 | 能把模糊需求带着别人收敛 | session 内容、PR/spec 文档 |
| **质量验证** | 跑一遍再说完成 | 看 diff + 有测试 | TDD 先行 + 向 AI 索要完成证据 | 为团队建质量闸/review 流程 | Gitea PR(diff、测试、CI 记录) |
| **自动化编排** | 会用现成 skill | 建过能稳定运行的 cron/监控 | 多 agent 委派、事件订阅、输出稳定性设计 | 沉淀过被他人复用的 skill | cron 列表、skill 仓库、投递记录 |

- L0 = 该维度尚无任何证据。
- 各级锚点的"线画在哪"不拍脑袋:由全员标定测评(§4.5)的数据确定——公司公认高手 90% 都做到的行为定为 L2/L3 锚点,普通员工中位数校准 L2。

### 2.2 安全合规:资格闸,不是等级

合规没有"做得比较好"一说(密钥不进仓库是 0 和 1),因此**从等级维度中剥离,做成每级晋升的前置 pass/fail 闸**:

| 闸 | 内容 | 不通过的后果 |
|---|---|---|
| S1(入门闸) | 密钥进 .env/keychain 不进仓库;一律走内部网关;测评中不泄露预埋 key | 不解锁 L2 课程与权限 |
| S2(进阶闸) | budget 与告警设置;approvals 档位理解;泄漏扫描与轮换流程 | 不解锁 L3(smart approval)权限 |
| S3(生产闸) | cron/自动化的投递兜底、模型成本选型、审计意识 | 不解锁 L4(生产 cron)权限 |

### 2.3 总等级:短板决定制

**驾照等级 = 四维中的最低级,且需通过对应安全闸。**

理由:等级兑换真实权限,一个需求表达 L4 但质量验证 L1 的人拿到 smart approval 是危险的。副作用(显得升级慢)恰好变成个性化引擎最简单的推荐规则——**永远优先补最短的板**(§5.2)。

### 2.4 等级获取路径

- **L0–L2:摸底测评可直接授予**(§4)。
- **L3/L4:只能用作品换**——课程大作业、毕业项目、被他人复用的 skill、真实仓库的合格 PR 等交付物,按每维的 rubric 评定。20 分钟测评区分不出 L3/L4,且"高等级用真实交付换"保证含金量。
- **导师背书直升通道**:资深 AI 工程师入职,由指定导师(L4 在职员工)背书可直升 L3/L4,免刷作业。背书记录留痕,导师对背书结果负责。

## 3. 用户旅程总览

```
注册/SSO 登录
   │
   ▼
摸底测评(33 min)────────────────┐
   │  自述 3min → 快筛 10 题 → 沙盒实操 20min
   │  输出:四维向量(L0-L2)+ S1 闸结果 + debrief 复盘屏
   ▼
选择环境模式
   │  A. 预配置(容器/一键脚本,默认)
   │  B. 从空白搭建一切(本身是 L3 认证课)
   ▼
个性化课程路径(动态装配,优先补短板)
   │  微课切片 → 实操任务 → 交付物提交(Gitea PR/Issue)
   │  每个交付物 → 信号提取 → 等级向量更新
   ▼
大作业 / 毕业项目(L3/L4 作品制入口)
   │  spec → 计划 → TDD → review → 验证 → 上线
   ▼
毕业:等级冻结,采集停止,权限按等级生效
   │
   ▼(此后完全自愿)
工具大版本发布 → 收到续证邀请(10min 增量课)→ 保持权限有效
月度 Demo Day / 随时回来查漏补缺
```

集中开营的轻量兼容:开营 = 给一批用户打同一个 cohort 标签 + 共享一个飞书群 + 统一的 Demo Day 日期,课程路径仍然是各自个性化的,不做任何额外的同步排课设计。

## 4. 摸底测评设计

### 4.1 结构:33 分钟三段漏斗

| 段 | 时长 | 目的 | 不做什么 |
|---|---|---|---|
| 自述 | 3 min | 岗位、用过什么工具、日常场景 → 决定沙盒从哪个难度起测 | 不计入等级 |
| 快筛 | 10 题 | 唯一目的:把完全零基础的人筛出来直接从 D0 起步,避免他们在沙盒里挫败 20 分钟 | 不用于定级 |
| 沙盒实操 | 20 min | 真正的摸底:行为信号采集 → 四维向量(L0-L2)+ S1 闸 | 不问"你为什么这样做" |

### 4.2 沙盒实操:一个复合任务,预埋四类信号源

不出四道题,出**一道复合任务**(真实工作里能力是同时使用的)。示例题干:

> 「这是团队的一个小工具仓库,接手一下:把 README 里过时的地方修掉,然后完成 Issue #7。用任何 AI 工具,做完提 PR。」

仓库经过精心布置:

| 埋点 | 测什么 | 采集的行为信号 |
|---|---|---|
| Issue #7 故意模糊("优化一下输出格式") | 需求表达 | 是否先让 AI 提问/自己追问验收标准,还是直接开干(gateway 日志可见) |
| 一个看似正常、实际必挂的测试用例 | 质量验证 | 是否跑测试;AI 说"完成"后是否验证;PR 是否附证据 |
| `config.py` 里预埋假 API key | 安全闸 S1 | key 是否被 commit 进历史;是否被发现并妥善处理 |
| 任务量刚好略超 20 分钟 | 工具操作+需求表达 | 是否收窄范围、分段交付,还是让 AI 一把梭到超时 |

配套设计:

- **沙盒内提供速查卡**(现有附录那张):测的是工作流本能,不是背命令。没用过这套具体工具的人不被惩罚。
- **结束必有 debrief 复盘屏**:揭开全部埋点("你注意到那个 key 了吗?第 7 个测试其实是挂的,你提交前跑了吗?"),配 asciinema 关键片段回放。测评本身即第一课;埋点公开化后,防埋点的唯一方法就是养成好习惯,测评长期反而更有效。

### 4.3 信号管道(全程零打扰)

| 管道 | 采到什么 |
|---|---|
| llm-gateway 请求日志 | 要没要计划、prompt 质量、/clear 使用、上下文管理 |
| 容器 instrumented shell(bash/zsh 钩子) | 跑没跑测试/程序、命令序列、退出码 |
| Gitea 服务端 | commit 粒度、diff、PR 描述、key 泄漏 |
| asciinema 会话录制 | debrief 回放、申诉证据、讲师抽查(纯文本,存储近乎免费) |

### 4.4 打分:信号 → 向量,规则透明

- 每个信号是一条 rubric 行("提交前运行过测试 → 质量验证 +1"),纯规则为主 + 少量 AI 判断(如"PR 描述是否含验收证据"用小模型判)。
- **规则对用户完全公开**(防的方法就是好习惯),每次判定留存证据链接,支持申诉重测。
- 测评输出:四维向量(每维 L0/L1/L2)+ S1 pass/fail + debrief。

### 4.5 全员标定测评(约 200 人,一次性战役)

三个收获,一次投入:

1. **等级校准**:高手与普通员工的行为分布画出 L1/L2/L3 锚点线,替代拍脑袋;
2. **内容金丝雀池**:补足随到随学模式下样本量不足的问题(志愿者可持续参与新内容试用);
3. **全公司 AI 适配度底图**:匿名聚合分布,用于争取资源和确定内容优先级。

**铁律**:个人分数仅本人可见;管理端只看匿名聚合。否则数据被应付/美化,标定全部失真。

## 5. 个性化课程引擎

### 5.1 内容架构:切片 + 元数据 + 动态装配

对抗"内容矩阵爆炸"(等级 × 工具 × 版本的乘法增长):课程不是预制文档,而是**原子切片的查询结果**。

每个切片是 `curriculum` 仓库(Gitea)里一个带 frontmatter 的 markdown:

```yaml
id: quality/verify-before-done        # 稳定 ID,路径即分类
dimension: 质量验证                    # 四维之一,或 safety-gate
level_edge: L1->L2                    # 服务哪条晋升边
type: demo | exercise | pitfall | quiz
tools: [claude-code, codex]
version_range: "claude-code >=2.0 <3.0"   # 版本适配
env: container | own-mac              # 在哪一层环境执行(§6)
depends_on: [setup/gateway]
verify:                               # 机验:发布闸和学员自检共用
  - cmd: "pytest -q"
    expect_exit: 0
grading_signals: [ran_tests_before_pr, read_diff]  # 供打分引用
source: 内部分享录屏切片链接 | generated
```

- 现有 10 课按此 schema 拆解为首批切片(演示剧本、实操清单、坑卡片天然就是切片粒度)。
- **旧版本共存**:同一 `id` 允许多个 `version_range` 变体,装配时按学员环境实际版本命中;保留最近 3–5 个版本变体,更老的自动归档。

### 5.2 装配算法

个性化路径 = 一次查询 + 拓扑排序:

```
输入:学员四维向量、安全闸状态、环境模式、工具版本
1. 过滤:选出 level_edge 落在学员当前边界上的切片,按 version_range 匹配环境
2. 排序:优先最短板维度(短板决定制 → 补最短板收益最大且规则唯一)
3. 拓扑:按 depends_on 排出可执行顺序
4. 插闸:安全闸切片强制排在对应等级解锁之前
输出:今日路径(微课 + 实操 + 交付物要求)
```

已掌握的维度自动整段跳过——这就是"让有基础的人跳过入门"的实现,不需要人工排课。

### 5.3 等级更新(仅课程期内)

每个交付物(PR、cron 截图、spec 文档)提交后触发信号提取 → rubric 打分 → 维度向量更新 → 路径重新装配。用户在个人面板看到:四维雷达图、每次升级引用的证据链接、距下一级还缺哪些行为。

## 6. 环境体系(纯终端,两层)

### 6.1 第一层:平台沙盒 —— Linux 容器 + web 终端

- **形态**:浏览器内嵌 xterm.js + ttyd,左侧任务说明/速查卡,右侧终端。点"开始"秒级进入,零本地依赖(新人第一天电脑没配好也能做测评,发个链接即可)。
- **承载**:摸底测评(标准化环境保证信号可比)、破坏性练习(/rollback、故意改坏文件)、全部 `env: container` 切片。
- **容量**:一台 64G 宿主机 + Docker 即可支撑 30 并发;预热 3–5 个已拉好镜像的容器池;容器 4 小时无操作自动回收。
- **"我的东西还在"**:每人一个持久卷(home、配置、作业仓库),容器随用随抛、卷永续。每次进入都是可复现环境,排错不用猜"你装了什么奇怪东西"。
- 不用 K8s、不做每人常驻虚机(伪需求)、不做预约调度。

### 6.2 第二层:学员自己的工作 Mac —— 真实环境

- 公司本来就给新人发 Mac,毕业后就在这台机器上干活——这是最真实的"真实环境",且学习到工作零迁移成本。
- 平台提供:**一条命令的预配置脚本**(现有 D0 清单的自动化,直接解决"配置复杂导致放弃")+ **课程采集器 CLI**(做 own-mac 任务时收集工件级信号:git 记录、命令退出码、测试输出)。
- 采集器采什么**全部公开可查**,且只在课程任务期间激活——契合不监控员工的原则。
- macOS 专属内容(Keychain 密钥管理、lark-cli 绑定)本来就是命令行操作,归入 `env: own-mac` 切片在这层完成。

### 6.3 明确不做(v1)

桌面环境、屏幕串流、共享真机 Mac 池、macOS 虚拟机——成本与复杂度均不匹配收益。共享真机方案被否决的三笔税记录在案:状态复位税(污染信号)、身份隔离税(前一学员的 key/飞书身份留在机器上,必然出安全事故)、调度税(与教学无关的预约系统)。若未来出现非 macOS-GUI 不可的课程内容,再评估小规模 Tart 虚拟机池。

### 6.4 "空白 vs 预配置"的落点

- **预配置** = 容器即开即用(默认,测评和 L1 全部在此,排除环境噪音);
- **从空白搭建一切** = L3 的一门认证课,在学员自己的 Mac 上完成("你能把这套环境给下一个新人搭起来吗"),搭建成果直接带走用,顺带培养未来的讲师/管理员。

## 7. 内容自动更新流水线(尽量全自动)

### 7.1 五段流水线(全部以 Hermes cron + skill 实现)

```
① 哨兵          cron 监控 npm/GitHub 上 claude-code、codex、hermes、lark-cli
                的发版与 changelog;订阅内部工具发布群
② 影响圈定      新版本号打到 version_range 索引 → 自动列出受影响切片清单
③ 再生成        agent 携带 changelog + 旧切片重写受影响切片,产出 diff(PR)
④ 三道质量闸    a. 可执行性验证:干净容器里真实跑切片的 verify 块,预期输出对上
                b. AI 评审员:按 rubric 审(口径、内部矛盾、坑是否仍成立)
                c. 金丝雀:先推给最近在学学员 + 全员池志愿者,看完成率/卡壳率
⑤ 发布          过闸自动合并上线 + 变更摘要;不过闸升级人工
```

### 7.2 人工介入的仅有两类

1. **结构性变更**:新增课程、删改能力模型、切片依赖图大改;
2. **安全红线内容**(第 9 课范畴)的任何改动。

其余(命令变更、版本号、输出示例过时)全自动闭环。

### 7.3 新工具发现(提示管理员,不自动引入)

哨兵额外订阅工具信息源(发布聚合、内部聊天中的工具讨论),聚类出候选新工具后自动生成**评估卡**推给管理员:它解决什么、与现有工具链重叠度、建议的切片位置、预估的课程改动量。管理员点头才进入流水线。

### 7.4 学员是内容传感器

"翻车 Top 10"来自真实事故,平台把这个采集自动化:AI 助教收到的求助、任务中的高频卡壳点、报错聚类 → 达到频次阈值自动起草候选 pitfall 切片 → 走同一套三道闸。**内容与时俱进的最大来源是学员踩坑,其次才是软件发版。**

### 7.5 技能续证(内容更新作用于"人的等级")

工具大版本发布时:相关维度等级打上"基于旧版"标记 → 给已毕业用户发一条通知("10 分钟增量课已上线,续证可保留 L3 权限")。**来不来完全自愿**;但 L3/L4 权限(高 budget、smart approval、生产 cron)的有效期与工具版本挂钩。不监控任何人,权限体系照样是活的。等级在毕业时刻冻结,更新只发生在用户自愿回来的那一刻。

## 8. 数据与隐私边界(硬约束)

| 阶段 | 采集范围 | 说明 |
|---|---|---|
| 测评/课程期间 | 沙盒内全量行为信号 + own-mac 任务的工件级信号 | 采集项公开可查;asciinema 录制用于 debrief 与申诉 |
| **毕业之后** | **零采集、零追踪** | 不读任何日常工作工件,不做聚合指标。避免监控感破坏员工行动与决策的松弛感 |
| 分数可见性 | 个人分数与证据仅本人可见 | 管理端永远只看匿名聚合分布 |
| 续证 | 用户自愿发起,采集仅限续证任务本身 | 同课程期规则 |

## 9. 运营机制

### 9.1 随到随学的同伴机制替代(必须提前设计,否则静默烂掉)

现有训练营里"评审人=旁边同事、讲师分组互评、毕业演示"在随到随学下全部失效,异步替代:

- **互评** → AI 助教评审(requesting-code-review 流程)+ 一位在职导师抽查;
- **毕业演示** → 录屏 + 异步评审(导师 + 一位 L3+ 员工);
- **社交能量** → **月度 Demo Day**:把当月毕业学员凑一场线上演示,同时是导师背书、优秀作品进选题池、优秀学员转讲师的入口;
- **答疑** → 训练营飞书群常驻 Hermes 机器人(常见坑做成 skill,越用越聪明),沿用现有设计。

### 9.2 讲师与管理员

- 轮值讲师机制沿用:senior 只负责新录 5–10 分钟片段,切片串联由内容流水线完成;
- 管理员日常工作收敛为三件事:审结构性变更 PR、处理新工具评估卡、看匿名聚合看板决定内容优先级。

### 9.3 平台自身的成功指标

| 指标 | 含义 |
|---|---|
| Time-to-first-PR | 新人从注册到第一个合格 PR 的时长(北极星) |
| 路径完成率 / 切片卡壳率 | 内容质量信号,直接反哺金丝雀闸 |
| 等级分布迁移 | 群体从 L1 向 L2/L3 的迁移速度(匿名聚合) |
| 续证率 | 工具大版本后 30 天内自愿续证比例(平台拉力的直接度量) |
| 内容新鲜度 | 工具发版到对应切片上线的时滞(目标 < 72h) |

## 10. 技术架构

### 10.1 组件图

```
┌─────────────────────────── Web 平台(单体起步)───────────────────────────┐
│  测评中心 │ 课程播放器(说明+内嵌 web 终端)│ 个人面板(雷达图/证据)│ 管理台 │
└───────┬───────────────┬──────────────────────┬─────────────────┬─────────┘
        │               │                      │                 │
   装配引擎         沙盒编排器              打分服务          内容流水线
 (切片查询+拓扑)  (Docker 池+持久卷      (rubric 规则+       (Hermes cron
        │          +ttyd+录制)           小模型判定)          + skills)
        │               │                      │                 │
┌───────┴───────────────┴──────────────────────┴─────────────────┴─────────┐
│                      既有基础设施(全部复用,不新建)                        │
│  Gitea(curriculum 仓库/作业仓库/PR)· llm-gateway(日志/budget/key)      │
│  Hermes(助教机器人/流水线执行体)· 飞书(通知/群/SSO)· PostHog(平台埋点)│
└───────────────────────────────────────────────────────────────────────────┘
```

要点:平台是既有工具链上的**薄编排层**,不重复建设。账号走飞书 SSO;作业与内容都在 Gitea;打分证据链引用 Gitea/gateway 的原始记录;对外开放的预留 = 把 Gitea/gateway/飞书封装成 provider 接口(v1 只实现内部一套)。

### 10.2 关键技术选型建议

| 部件 | 建议 | 理由 |
|---|---|---|
| 沙盒 | 单宿主机 Docker + 预热池 + 每人持久卷 | 30 并发不需要 K8s;可复现、秒级、零调度 |
| Web 终端 | xterm.js + ttyd(或 sshpiper) | 成熟、纯 TTY、易嵌入 |
| 会话录制 | asciinema 格式 | 纯文本、近零存储、可回放可搜索 |
| 内容存储 | Gitea 仓库 markdown + frontmatter | 内容即代码,PR 即审核流 |
| 打分 | 规则引擎为主 + 小模型判定为辅 | 可解释、可申诉、成本低 |
| 流水线 | Hermes cron + skill | 吃自己的狗粮,平台本身是课程的活教材 |

## 11. MVP 路线图

### Phase 0 · 地基(2–3 周)

- 定稿能力模型 rubric(四维 × 五级行为锚点 + 三道安全闸清单);
- 现有 10 课拆解为首批切片(约 60–80 个),打上 schema 标签;
- 沙盒最小实现:Docker 池 + web 终端 + 持久卷 + shell 钩子。

### Phase 1 · 测评 + 手动路径(3–4 周)

- 沙盒实操测评上线(复合任务仓库 + 埋点 + 信号管道 + debrief);
- 打分规则引擎 + 个人四维面板;
- 路径先用装配算法生成、人工抽查放行(装配引擎跑在"建议模式")。
- **里程碑:第一批真实新人走完"测评 → 个性化路径 → 毕业"。**

### Phase 2 · 标定 + 自动装配(3–4 周)

- 全员标定测评战役(约 200 人,志愿 + 部门动员),校准等级线;
- 装配引擎转全自动;等级兑换权限(budget/approval)接通 llm-gateway;
- AI 助教机器人进飞书群;月度 Demo Day 启动。

### Phase 3 · 自动更新流水线(4–6 周,可与 Phase 2 并行)

- 哨兵 + 影响圈定 + 再生成 + 三道闸 + 自动发布全链路;
- 新工具评估卡;学员卡壳点 → pitfall 切片管道;
- 技能续证通知与权限有效期挂钩。

### 明确推迟

对外开放版、桌面/GUI 环境、Mac 虚拟机池、移动端、多语言。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 测评被"应试"(埋点被口口相传) | 埋点本来公开(debrief);防埋点的唯一方法就是好习惯,即测评目的本身;定期轮换任务仓库变体 |
| 全自动更新产出错误内容 | 三道闸中"可执行性验证"是硬闸(命令跑不通必拦);红线内容永远人工;每次发布附变更摘要可回滚 |
| 短板制让用户觉得升级慢、有挫败感 | 面板突出"最短板 + 距下一级还差哪 2 个行为",把挫败转为明确的下一步;维度分与总等级并列展示 |
| 全员标定被视为考核,数据失真 | 铁律:个人分数仅本人可见,管理端只看匿名聚合;宣传口径为"帮公司校准课程难度" |
| 导师背书通道被滥用 | 背书留痕、导师实名负责、背书者作品事后可抽查 |
| 内容切片粒度切错(过碎/过粗) | 以现有课程的"演示剧本/实操清单/坑卡片"为天然粒度起步,凭卡壳率数据再调 |
| 平台没人回来(毕业后拉力不足) | 续证与权限有效期挂钩;Demo Day;新工具/新版本的增量微课推送(通知可退订) |

## 附录 A · 已否决方案备忘

| 方案 | 否决理由 |
|---|---|
| 答题式摸底测评 | 测知识不测行为;核心能力(验证习惯、上下文管理)选择题测不出 |
| 预制多版本课程文档 | 内容矩阵乘法爆炸,自动更新救不了;改用切片+装配 |
| 每人常驻虚机 | 伪需求;"我的东西还在"用持久卷解决 |
| 共享真机 Mac 池(远程控制) | 状态复位税、身份隔离税(安全事故必然发生)、调度税 |
| 桌面环境/屏幕串流 | 成本与难度不匹配;课程九成内容纯终端 |
| 毕业后持续采集聚合指标 | 主动放弃:不监控员工,保护行动与决策的松弛感 |
| 按百分比金丝雀 | 随到随学下样本不足;改为最近学员+全员志愿池 |
