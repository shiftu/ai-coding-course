🤖 AI Coding 微课堂

两周新人训练营 —— 把内部技术分享切片串联成课程，让新人在入职前两周跨越工具门槛，把精力留给业务思考
⏱ 10 期 × 30-45 分钟 👥 对象：新入职工程师（0-2 年） 🛠 基于公司真实工具链 ✍️ 每期有演示 + 实操 + 交付物

📌 课程定位与设计原则

从"求人"到"自助"：新人的两周不是用来背文档的，而是学会一套与 AI 共事的作业方式 —— 让 AI 承担查找、实现、验证、汇报的体力活，把精力解放给业务策略思考。

三段式结构（每期）：

🎬 演示（10-15 min）
讲师按「演示剧本」现场操作录屏。剧本已经写好，照着敲即可，无需临场发挥。
🖐 实操（20-30 min）
学员按「实操清单」自己动手，每步附预期输出，卡住能自检。做完交「交付物」到课程仓库。

素材串联机制：每期标注「复用现有录制」+「新录片段」，技术分享不用重新讲，只补首尾衔接和实操引导。讲师轮值：每期由一位 senior 认领，只负责新录的 5-10 分钟片段。

Day 0 · 开营准备（自选动作，开营前一天）

0环境清单：把武器先领了约 30 分钟 · 管理员提前开通权限
目标：每个新人开营前拥有完整账号与工具链，第 1 课直接开讲，不浪费课堂时间。
✅ 人员开通（HR/IT 在新人入职当天完成）
  • Gitea 账号（gitea.jiangtao.lol，加入 ai-workshop 组织）
  • llm-gateway 团队 + API Key（管理员在网关建 team=新人姓名，发 ak_xxx；配月度 budget）
  • 飞书开发者/机器人权限（新人自己的 Hermes 会话用）
  • PostHog / Prometheus / SigNoz 只读账号
🛠 新人本机安装（步骤，按序执行）
  1. 确认 llm-gateway 连通：curl -s http://127.0.0.1:7421/v1/models -H "Authorization: Bearer $LLM_GW_KEY" | head -5 → 见到模型列表即通（注意用 127.0.0.1，公网域名会被 WAF 拦 403）
  2. 安装 Hermes Agent：curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
  3. 体检：hermes doctor → 全绿通过
  4. 安装 Claude Code：npm install -g @anthropic-ai/claude-code；Codex：npm install -g @openai/codex
  5. 两个都指向内部网关（环境变量：ANTHROPIC_BASE_URL=http://127.0.0.1:7421/v1、OPENAI_BASE_URL=http://127.0.0.1:7421/v1，Key 用 llm-gateway 发的）
  6. 安装 lark-cli：npm install -g @larksuite/cli
  7. Fork 课程练习仓库 ai-workshop/playground 到自己名下，git clone 到本地
⚠ 常见坑
  • 用公网域名 llm.jiangtao.lol 直连 → Cloudflare WAF 403「Your request was blocked」。一律走 127.0.0.1:7421。
  • Key 必须存 ~/.hermes/.env 或 macOS Keychain，严禁 commit 进仓库。

第 1 课 · 工具全景：找到你的 AI 工具箱（D1）

1内部 AI 工具地图长什么样40 min · 素材：复用内部 Hermes 技术分享 + 新录 5 min
目标：建立全局心智 —— llm-gateway 是"水电"（统一模型出口），三个入口（CLI 结对 / Hermes 数字员工 / 飞书机器人），一套数据平台（PostHog/Prometheus/SigNoz），一个协作中枢（Gitea）。
🎬 演示剧本（讲师 10 分钟）
  1. 画架构图：llm-gateway（127.0.0.1:7421）← Claude Code / Codex / Hermes / 飞书机器人，全部同源
  2. 现场验证网关：curl http://127.0.0.1:7421/v1/models -H "Authorization: Bearer $KEY" 展示模型清单
  3. 打开 hermes status / hermes doctor，展示本机已连的飞书、Telegram、微信通道
  4. 打开 Gitea 组织页面，指出练习仓库、Issue/Milestone 用法（公司规范：计划同步到 Milestone，不写外部 md）
  5. 演示一次「一句话派活」：hermes chat -q "查一下这个仓库最近 7 天的 commit 统计"（在 playground 目录）
🖐 实操清单（25 分钟）
  1. 完成 Day0 清单；在 ai-workshop 组织的 Issue 里报到（标题：名字 - 第1课）
  2. 依次跑 claude --version、codex --version、hermes --version、lark-cli doctor，四条命令全部有输出版本号 → 预期输出：无 error
  3. 在 playground 仓库目录跑 hermes chat -q "README 里哪些命令是过时的？列出 3 处" → 预期输出：3 条带行号的结论
  4. 把这次对话的 session 重命名：hermes sessions rename <ID> "第1课-仓库体检"
  5. 在 Gitea 练习仓库建第一个 Milestone「两周训练营」，把 Day0-D10 各建一个 Issue 挂进去（教学如何用 Milestone 跟踪计划）
⚠ 坑
  • 不要同时开三个入口做同一件事 —— 先选一个主入口，入门期用 CLI（可读性强、能看日志）。
  • 「版本号没打出来」90% 是 npm 目录不在 PATH，报给讲师，5 秒解决，别自己折腾。

第 2 课 · Claude Code / Codex：第一个结对工程师（D2）

2让 AI 写第一段真代码45 min · 素材：复用任一「AI 结对编程」内部分享 + 新录 8 min
目标：掌握 CLI 结对工程师的完整工作循环 —— 给需求 → 审计划 → 看着它实现 → 自己验证 → 提交 PR。同时学会"防 AI 乱来"的三个开关。
🎬 演示剧本（15 分钟，在 playground 仓库）
  1. 展示任务：给仓库加一个 dedup.py（对日志里的重复行去重并统计），需求一句话说清
  2. 先开新分支：git checkout -b feat/dedup；进入 claude 或 codex
  3. 让它先讲计划再动手（Claude Code 用 plan 模式 / Codex 用 --approval-mode 或先问它）→ 展示 AI 的计划，讲师说"这里范围大了，先做输入和去重，统计放 V2"，收窄
  4. 放它实现（演示不要一次放全程 —— 分两段：先核心函数，验收后再补 CLI 入口）
  5. 不信任自报：讲师自己跑 python3 dedup.py samples/dup.log | head，手工核对输出，再 git diff 审一眼改动
  6. 提交 & 推送，在 Gitea 建 PR（关联第 1 课的 Issue）
  7. 演示 /clear（每阶段开新上下文）与 checkpoint（git commit 就是人类最好的 checkpoint）
🖐 实操清单（30 分钟）
  1. 在 playground 里选一个练习 Issue（讲师预埋 5 个小任务：加参数、改文案、写单测、修 bug、写 README 片段）
  2. 新分支 → 进 CLI agent → 先要计划 → 用一句话收窄范围 → 放它实现
  3. 自己验证：跑起来、给真实输入、对输出；用 git diff 通读一遍改动（看有没有删了无关代码 / 引入魔法常量）
  4. 提 PR 到 ai-workshop/playground，标题带 Issue 号（如 #12 feat: 添加 --dry-run 参数）
  5. 交付物：PR 链接 + 一句话复盘（哪一步 AI 帮最多、哪一步它在瞎搞）贴到自己的 Issue
⚠ 坑
  • 别让它一口气写完 300 行再回来 —— 计划一次、实现一次、验证一次，节奏要可控。
  • 它说"完成了"不算数，你要跑一遍并看过 diff 才算数（这是全课最重要的习惯，第 5 课会强化）。
  • 改需求时先 /clear 或明确说"忽略上一条"，否则它会把新旧需求缝在一起。
  • 全权限模式（--dangerously-skip-permissions）新手禁用，先学会审。

第 3 课 · Hermes Agent：团队的数字员工（D3）

3从"对话工具"到"有记忆的同事"45 min · 素材：复用内部 Hermes 分享 + 新录 10 min
目标：理解 Hermes 与 CLI 结对工具的本质区别 —— Skills（会积累的做法）+ Memory（记得住你是谁）+ Tools（真能操作系统），并学会把重复劳动"外包"给它。
🎬 演示剧本（15 分钟）
  1. hermes 开一个会话，演示三个真正有用的能力：
  2. tools：/tools 看工具清单（web / terminal / file / delegation / cronjob…），演示让它 搜索"AI Agent 本周新闻" 并总结 3 条
  3. skills：hermes skills list 展示内部沉淀的技能库（PostHog 分析、周报生成、健康检查…），演示加载一个 skill 后行为变化：hermes -s posthog-analysis chat -q "这个月的 DAU 趋势"
  4. memory：让它记住"我在第 3 课学员组，打招呼用中文"，然后开新会话验证它还认识你（hermes --continue）
  5. delegate：演示把一个大任务拆给子代理并行跑：delegate_task 同时查 3 个仓库的 README 并对比
  6. gateway 演示：在飞书私聊里给机器人发同一个问题，机器人带着全部工具干活（数字员工 7×24 在岗）
🖐 实操清单（30 分钟）
  1. 给自己建独立的 Hermes 配置（hermes profile create <名字>），配成内部网关模型
  2. 在会话里让 Hermes 记住你 3 个偏好（如"代码注释用英文"），然后 hermes --continue 开新会话验证记忆生效 → 预期：它自己说出你的偏好
  3. 用 hermes chat -q 一次性完成：查 playground 的 TODO 注释数量 + 列出前 5 条 → 输出到 todo-report.md
  4. 体验 /rollback：让它故意改坏一个文件，用 checkpoint 恢复（演示"AI 闯祸有后悔药"）
  5. 交付物：把上面 4 步的 session 链接（@session:.../... 或 hermes sessions list 截图）发到 Issue
⚠ 坑
  • 子代理的结果是自报成绩，不是事实 —— 它说"上传成功"你要自己验证（第 5 课有真实翻车案例）。
  • 技能是团队的资产：发现技能过时或漏步骤，当场 skill_manage 修掉，别憋着。
  • cron / 后台任务跑完要检查投递；没收到通知 ≠ 没干活，也可能是投递目标写错。

第 4 课 · 把需求说清楚：从一句话到可执行 Spec（D4）

4AI 时代的第一生产力：写清楚问题40 min · 素材：复用需求评审相关分享 + 新录 8 min
目标：明白"AI 不会替你思考需求"。学会一分钟的 brainstorming → 结构化 spec → 可执行计划 → 执行的流水线，让 AI 的产出可预期。
🎬 演示剧本（15 分钟）
  1. 拿一个真实模糊需求："优化一下 playground 仓库的 README 体验"（大家都会遇到的原话）
  2. 先让 AI 提问（brainstorming）：一次一个问题，挖出"读者是谁 / 痛点是什么 / 成功的标准"—— 引导出 3 个关键约束
  3. 把约束写成一页 spec：目标 / 范围（含"不做"）/ 验收标准 / 交付物
  4. 用 spec 生成实施计划（writing-plans）：拆成 5 个 bite-size 任务，每个任务有路径和验收
  5. 按计划执行（executing-plans），展示"计划先行"和"直接开干"的耗时差异（约 1:3）
  6. 总结金句模板：「用户 + 场景 + 现状痛点 + 期望 + 验收」五要素，贴上墙
🖐 实操清单（25 分钟）
  1. 从讲师给的 3 个模糊需求里选 1 个（如"给 playground 加个有用的工具"）
  2. 逼 AI 先问 3 个问题再动手；把五要素填进 spec 模板（仓库 docs/spec-template.md）
  3. 用 spec 生成计划 → 让 AI 自评计划（找 1 个遗漏风险），修正后再执行
  4. 交付物：spec + 计划 + 执行结果三位一体提交 PR，评审人 = 旁边的同事（讲师分组）
⚠ 坑
  • 模糊需求直接让 AI 写码 = 高概率白干，返工成本远大于思考成本。
  • Spec 里必须写「不做什么」（YAGNI），否则 AI 会把范围越滚越大。
  • 验收标准要可测量："加载更快"❌ → "P95 从 800ms 降到 400ms 以下"✅。

第 5 课 · 质量守门员：TDD + 自动 Review + 验证（D5）

5AI 写得快，谁来保证对？45 min · 素材：复用 Code Review 规范分享 + 新录 10 min
目标：建立"AI 产出必须过三道闸"的习惯 —— 测试先行（TDD）、提交前自动 review、完成前独立验证。这是全营最重要的一课。
🎬 演示剧本（15 分钟）
  1. TDD 红绿重构：先写测试（红）→ 让 AI 实现到绿 → 重构。演示"先测试后代码"如何天然约束 AI 不乱来
  2. 自动 Review：拿一个"看起来没问题"但有 3 个隐患的 diff（yes 安全漏洞/魔法数字/日志泄漏），让 agent 按 requesting-code-review 流程审 → 逐条命中
  3. 验证闭环：演示真实翻车案例 —— 子代理汇报"图片已上传"，实际 404。结论：agent 每报一个"完成"，都要问"证据呢？给我 URL / 文件路径 / 测试输出"
  4. verification-before-completion：演示交付前 checklist（跑全量测试、看真实输出、检查 diff、检查日志无报错）
🖐 实操清单（30 分钟）
  1. 挑一个练习 Issue，先用 pytest 写 3 个失败断言（红），再放 AI 实现到全绿
  2. 提交前让 agent 评审自己的 diff，把发现的问题修掉，记录"AI 审出 2 个，人工又发现 1 个"
  3. 在 PR 描述里附上验证证据：测试输出截图 / 命令输出 → 预期：评审同事不需要再问"跑过没有"
  4. 交付物：一个"测试红→绿"的 PR + 三段提交说明（测试/实现/验证）
⚠ 坑
  • "AI 写的代码不用测"是最大的幻觉 —— AI 生成代码的出 bug 率取决于上下文完整度，测试是唯一保险。
  • 自动 review 能抓 80% 的机械问题，但业务语义正确性只能人来判断。
  • 收到 review 意见先理解再改（receiving-code-review 流程），不要条件反射反驳或盲从。

第 6 课 · 数据自助：PostHog / Prometheus 不求人（D6）

6以后查数别排队了40 min · 素材：复用埋点/数据平台分享 + 新录 8 min
目标：用自然语言查询公司数据平台 —— 产品看 PostHog（活跃/漏斗/付费转化）、基础设施看 Prometheus（成本/资源）、线上问题看 SigNoz（链路/trace），全程不写一行 SQL。
🎬 演示剧本（12 分钟，用 preloaded 的 posthog-analysis skill）
  1. 演示三连问：hermes -s posthog-analysis chat -q "昨天 DAU 多少？新老用户各多少？"
    • 口径现场讲清楚：总 DAU = Active Action 事件，新用户 = S-UserRegister（首次打开自动游客注册），老用户 = 总 - 新
  2. 漏斗："从首页浏览到付费的转化漏斗，哪一步流失最大？" → 图表 + 结论
  3. 成本：用 Prometheus 查本月 AI token 花费趋势（accrush-cost-tracking / aws-cost-explorer skill）→ 展示"钱花在哪"
  4. 线上问题：SigNoz 查最近 1 小时最高错误率的服务 → 定位到一条 trace
  5. 演示一键周报：让 agent 生成交互式 HTML 周报（含 WoW 对比、异常标记），本地起服务给链接
🖐 实操清单（25 分钟）
  1. 用自然语言查 3 个指标：昨日 DAU、日新增、付费转化（用演示里的口径核对数字是否一致）
  2. 查一次你自己的项目/用户在事件里的活跃度，写一句业务结论（"新用户首日留存偏低"类）
  3. 把某一天的会话/事件数据导出到本地 CSV，head 看前 5 行 → 预期：列名与文档一致
  4. 交付物：Issue 里贴 1 个查询的结论 + 1 张图 + "口径说明"（为什么是这个数）
⚠ 坑
  • 看数据先讲口径：New/DAU/转化在不同团队定义可能不同，先对齐"事件定义"再下结论。
  • 按 bot_id 而不是 bot_name 关联事件（同一 bot 在不同事件类型里名字可能不一致）。
  • 成本数据有 1-2 天延迟，别拿昨天的数当实时数。

第 7 课 · 自动化与订阅：让机器自己干活（D7）

7把"每天要做的重复事"变成 cron45 min · 素材：复用监控/告警分享 + 新录 10 min
目标：学会三类自动化 —— 定时任务（cron）、状态监控（只报变化）、事件订阅（webhook），从此"重复劳动不占用人"。
🎬 演示剧本（15 分钟）
  1. 定时任务：现场建一个每天早上 9:30 的「每日站会摘要」cron —— 拉日历 + 任务，汇总成 3 行推给飞书（lark-workflow-standup-report）→ hermes cron create "30 9 * * *"
  2. 状态监控：给内网某 URL 挂健康检查（health-check-monitor），故意停掉服务 → 几分钟后只收到一条"DOWN"通知；恢复后再收一条"UP"（只报变化，不刷屏）
  3. 事件订阅：webhook 订阅一个外部事件源，事件发生时 agent 自动处理并回复
  4. 行业情报：展示每日 AI Agent 趋势摘要 / 设计周刊的 cron 输出长什么样（复用已有订阅）
  5. 演示投递配置：origin（回当前会话）/ 指定飞书群 / 失败时的错误告警
🖐 实操清单（30 分钟）
  1. 建一个自己的 cron：每天下班前自动汇总当天 Issue/PR 状态到飞书私聊 → hermes cron create，hermes cron list 确认在列
  2. 给 playground 的 CI URL 挂一个健康检查，验证收到一条通知（建议先让它失败一次看报警）
  3. 把 cron 手动触发一次：hermes cron run <ID>，验证投递内容 → 预期：飞书收到消息
  4. 交付物：cron 任务截图 + 一条真实投递消息转发到 Issue
⚠ 坑
  • 监控脚本输出必须稳定（不要带时间戳/随机顺序），否则每次 tick 都算"变化"，天天报警。
  • cron 的 prompt 必须自包含 —— 它运行在一个全新会话里，没有你刚才说的话。
  • 自动化也要有兜底：非零退出会发错误告警，这是特性（能及时发现 broken watchdog），别关掉。

第 8 课 · 飞书生态：文档 · 表格 · 审批 · 机器人（D8）

8让 AI 帮你过一遍飞书里的行政活40 min · 素材：复用飞书/Lark 开发分享 + 新录 8 min
目标：用 lark-cli 打通飞书全家桶 —— 云端文档、多维表格、电子表格、日历、会议纪要、审批、通讯录。日常"跟飞书死磕"的时间归零。
🎬 演示剧本（12 分钟）
  1. 会议纪要：汇总最近一周的会议纪要，生成结构化周报（lark-workflow-meeting-summary）→ 一键产出 Markdown 报告
  2. 多维表格：读一张业务 Base 表，问"最近 30 天新增了多少条记录，按负责人分组" → 直接得到分组统计（lark-cli bitable record search）
  3. 文档：让 agent 把一份草稿整理成飞书云文档并发出去（lark-cli doc create）
  4. 审批/考勤：查待办审批列表、考勤打卡记录（谁补卡了）—— 演示"数据自己会说话"
  5. 展示 lark-cli doctor 与身份绑定（bot-only vs user-default 的区别）
🖐 实操清单（25 分钟）
  1. 让 agent 汇总你最近 3 场会议的标题 + 待办事项，输出一张 Markdown 表
  2. 在练习多维表格里建一张「训练营作业登记表」，用 lark-cli 写入今天这条作业记录
  3. 把第 5 课的 PR 内容整理成一页飞书文档（标题/摘要/链接一键生成），分享给讲师
  4. 交付物：飞书文档链接 + 参会人待办截图贴 Issue
⚠ 坑
  • 身份权限：只读场景用 bot-only，别乱绑定 user-default 去操作别人的资源。
  • lark-cli 初始化的坑（keychain 写入失败等）—— 遇到先跑 lark-cli doctor，按提示走 stdin 方式补凭证，别重开。
  • 写操作（发文档、建表格）执行前让 agent 把内容念给你听一遍。

第 9 课 · 工程红线：成本 · 安全 · 合规（D9）

9用 AI 的边界在哪里40 min · 素材：复用安全/成本治理分享 + 新录 8 min
目标：成本看得见、密钥留得住、操作可撤销、数据不出境。学会用工具而不是靠自觉守住红线。
🎬 演示剧本（12 分钟）
  1. 成本：llm-gateway 查自己 team 的用量与 budget（list_budgets），现场设置一个月度告警阈值；AWS 成本浏览器展示当前 run-rate 和费用大头（真实数据：某环境月 ~$1.1K，关停省 ~$360）
  2. 密钥：演示「密钥进 .env / keychain，不进仓库」；git log -S "sk-" 展示如何查历史泄漏；启用 hermes config set security.redact_secrets true（输出自动打码）
  3. 权限：approvals 三档（manual / smart / off），演示 smart 模式怎么自动放行低风险、拦截高危命令（rm -rf 类）
  4. 审计：展示 agent 的会话记录/session 搜索 —— 所有 AI 干过的活都有迹可循（hermes sessions list / session_search）
  5. 合规一句话：内部数据走自托管网关，公网模型只进脱敏数据
🖐 实操清单（25 分钟）
  1. 查自己 team 过去 7 天的 token 用量和花费，写一句"我的 AI 使用画像"
  2. 给自己设一个月 budget 和用量告警阈值 → 预期：超阈值会收到通知
  3. 扫描 playground 仓库有没有疑似密钥泄漏（git log -S "ak_" --oneline、grep -r "sk-"）→ 预期：0 处或找到练习埋的 1 处（讲师预埋的）
  4. 把密钥全量迁移进 ~/.hermes/.env（权限 600），删除仓库里的任何明文凭据
  5. 交付物：Issue 贴 3 句成本结论 + 密钥扫描结果
⚠ 坑
  • 别用旗舰模型跑 cron/批处理 —— 换对模型成本差 10 倍，效果一样。
  • 密钥一旦进 git 历史，删文件不够，要 rotation + 清洗历史。
  • 成本查询有延迟（1-2 天），做决策用周粒度而不是时点。

第 10 课 · 毕业项目：两周内交付一个真实功能（D10）

10把 9 课串成一条流水线半天 · 素材：讲师演示往年毕业项目 + 新录 5 min
目标：独立跑完「想法 → 提问收敛 → Spec → 计划 → TDD 实现 → 自动 Review → 验证 → 上线 → 数据验证」全流程，交付一个真实可用的小功能（不是玩具）。
🏆 选题池（讲师提供，也可自选，须过验收）
  • A. 给团队做一个「每日站会摘要」bot（日历 + 任务 + 待办 → 飞书群每日推送）
  • B. 给内网服务做「健康检查 + 状态变化告警」监控
  • C. 用 PostHog 数据做一张团队专属周报（HTML，含异常标记，每周自动生成）
  • D. 自选：一个你入职后真实遇到、想解决的重复劳动
🎬 流程（讲师 15 分钟演示标准答案，学员半天实操）
  1. 15 分钟：讲师用选题 A 完整演示一遍流水线（压缩版），学员抄流程不抄代码
  2. 学员选题目 → brainstorming 收敛到 5 要素 spec → 挂到 Gitea Milestone「两周训练营」
  3. 计划 → TDD → 实现（允许 CLAUDE/CODEX/Hermes 任意组合，必须提交 AI 协作日志：哪步是 AI 干的）
  4. 自动 review + 人工互评 → 修 → 合并 → 上线/部署 → 用数据验证生效
📦 交付物 & 评分
  1. PR（含 spec + 测试 + 验证证据，合并到 playground 或真实仓库）
  2. 5 分钟演示（讲师 + 1 位同事评审）
  3. 复盘 3 条：AI 帮你省了什么 / 哪里差点翻车 / 下两周要沉淀什么技能

评分权重：流程完整 40%（spec/test/验证一个不少）+ 真实可用 30% + 演示质量 20% + 复盘深度 10%。

⚠ 坑
  • 毕业生最常见的失败：绕开 TDD 直接"让 AI 一把梭"，上线后发现回滚成本更高。
  • "上线"定义要小：跑通 + 有人用 + 有日志，就算上线，别追求完美。

🎓 教学运营建议（给 HR / 讲师）

  • 轮值讲师：10 期分给 5-6 位 senior，每人新录 5-10 分钟，复用素材由课程主编（可以是 Hermes 自己）把切片串联进统一模板。
  • 场地设施：每人一台能开终端和浏览器的 Mac；讲师投屏 + 录屏软件（演示即素材，一鱼两吃）。
  • 打卡机制：每期交付物贴到 Gitea Issue（Milestone 跟踪），漏交的在训练营群里艾特，不补交的毕业评审减分。
  • 答疑渠道：训练营飞书群常驻一个 Hermes 机器人接新手问题（把常见坑做成技能，机器人越用越聪明 —— 这就是 skill 沉淀的正循环）。
  • 复盘沉淀：10 期结束后，让 Hermes 汇总全部学员 Issue，产出《训练营 FAQ 手册 v1》并沉淀为技能，下期训练营直接复用。
